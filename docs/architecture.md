# Acropad Architecture

This document describes the technical architecture of the active Acropad desktop application (`advanced/`), pairing a Flutter user interface with a native Rust core via `flutter_rust_bridge`.

## 1. High-Level Architecture

Acropad follows a layered architecture separating visual presentation, reactive state management, FFI communication, and native filesystem operations:

```text
+-----------------------------------------------------------+
| Flutter Desktop UI (Dart)                                 |
| - lib/ui/: VaultExplorer, EditorPane, QuickSwitcher       |
+-----------------------------▲-----------------------------+
                              │ Events & States
+-----------------------------▼-----------------------------+
| Reactive State Management (BLoC)                          |
| - VaultBloc: Vault path, file discovery tree, active note |
| - EditorBloc: Buffer state, dirty tracking, debounced save|
+-----------------------------▲-----------------------------+
                              │ Asynchronous FFI Calls
+-----------------------------▼-----------------------------+
| flutter_rust_bridge (FRB v2.11.1) Layer                   |
| - lib/src/rust/api.dart <---> native/src/api.rs           |
+-----------------------------▲-----------------------------+
                              │ Thread Boundary
+-----------------------------▼-----------------------------+
| Native Rust Engine (Rust)                                 |
| - Directory scanning via walkdir (ignoring .git, etc.)    |
| - In-vault content substring search                       |
| - Filesystem read/write operations                        |
+-----------------------------------------------------------+
```

## 2. Component Layers

### 2.1 UI Layer (`advanced/lib/ui/`)
- Built using standard Flutter Material desktop components.
- Responsive split-view layout featuring a collapsible sidebar navigation tree and a monospace editing pane.
- UI components strictly react to states emitted by BLoC providers; no direct filesystem I/O is performed in UI widgets.

### 2.2 State Management (`advanced/lib/bloc/`)
- **`VaultBloc`**: Manages vault selection, invokes native directory scans, caches discovered note paths, and handles vault-wide filtering.
- **`EditorBloc`**: Holds the current note buffer, tracks unsaved changes, and orchestrates debounced disk writes to avoid thrashing I/O during active typing.

### 2.3 FFI Bridge Layer (`advanced/lib/src/rust/` & `flutter_rust_bridge.yaml`)
- `flutter_rust_bridge` provides typed Dart-Rust bindings generated by `flutter_rust_bridge_codegen`.
- Bridges asynchronous Dart `Future` calls to Rust functions running in background threads without blocking the Flutter UI isolate.

### 2.4 Native Rust Core (`advanced/native/src/api.rs`)
- **Vault Traversal (`scan_vault`)**: Recursively enumerates `.md` and `.txt` files using the `walkdir` crate. Automatically filters hidden directories (e.g., `.git`, `.obsidian`, `.trash`).
- **Vault Search (`search_vault`)**: Scans files for matching query substrings, returning file metadata and matched snippets.
- **File I/O (`read_file`, `write_file`)**: Robust file reading and writing with Rust standard library error handling (`std::fs`).

## 3. Thread and Memory Boundaries

- **UI Isolation:** The Flutter event loop runs on the main platform thread. UI responsiveness is preserved by offloading all file traversal and content search tasks across FFI.
- **Rust Worker Pool:** Asynchronous calls made through FRB execute in Rust's background thread pool.
- **Memory Safety:** Data passed across the FFI boundary uses typed memory buffers managed by FRB runtime. Native Rust memory is released deterministically when operations complete.
